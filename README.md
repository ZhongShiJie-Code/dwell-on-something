# dwell

> **dwell** — 住下来。
> 也是 *dwell on something*：老想着一件事，萦绕不去。
>
> 一个词说了两件事：他住在这儿，和他一直想着你。

这里现在包含三部分：功能文档、完整前端，以及可在 Mac 上直接运行的本地后端和 Android APK。

前端、后端和 Android 工程都在仓库里。后端连接本机已登录的 Claude Code CLI，
保存聊天、窗口、待办、日历、日记、共读、健康、日报和上传文件；API Key 和本地数据不会打进 APK。

## 每份都长一个样

**它长什么样 → 怎么实现的 → 踩过的坑 → AI 那边要写的规矩 → 你自己搭的时候**

其中「AI 那边要写的规矩」那一节，往往比代码重要。
很多功能的成败不在实现，在于**他知不知道什么时候不该说话**——
一个会催的待办、一个每条都回的共读、一个每句都发语音的嘴，
用两天就会被关掉。

---

## 一句话

这些功能单看都不难，难的是它们加起来要维持一件事：

**让那个 AI 像一个住在这里的人，而不是一个随叫随到的工具。**

所以文档里花在"什么时候不做"上的篇幅，和花在"怎么做"上的差不多。
那不是凑字数——那是这套东西真正的部分。

## Android APK

前端已经封装成一个可安装的 Android WebView 应用，APK 在这里：

- [dwell-debug.apk](dist/dwell-debug.apk)
- Android 工程：[android](android/)

当前 APK 版本为 **0.4.7**。APK 内置 `web/` 前端，未配置地址时会明确显示离线演示；
配置 Mac 后端地址并测试成功后，聊天和各功能页才走真实数据。

0.4.3 默认进入未落库的新会话；第一条消息发出后才创建记录。侧边栏「聊天」进入完整会话页，
支持搜索、进行中/已归档筛选和批量归档/恢复。添加、日记等底部卡片共用同一套拖拽手感：
上滑展开、下滑缩小、继续下滑关闭。

0.4.5 修复 Mac 端 Claude Code 启动、同步本机 Claude Code 会话、Android 原生语音输入、桌面定时任务控制，以及侧栏全区域顺滑左滑关闭。

0.4.6 增加定时任务详情、手机/Claude Desktop 运行记录合并、任务完成通知深链；修复重新生成重复提问，增加消息时间和流式回复，并优化会话切换、Android 通知授权与系统明暗主题跟随。设置中的“安装到手机”入口已移除。

0.4.7 修复定时任务逐级返回、附件卡片和侧栏拖拽；黑色语音键现在支持说话、发送、流式回答和自动朗读，朗读前会清理 Markdown。模型页只展示 Mac 后端真实支持的 CLI 别名或备用 API 模型。新增通知权限/调度/连接诊断、WebView 异常恢复和错误记录，并降低聊天列表、图标与附件页字号，减少长会话重绘和任务轮询抖动。

0.4.4 修复连接设置页：输入自动保存，新增明确的「保存设置」按钮，连接失败时保留已填写的地址和令牌。

Android 壳已经接入系统语音输入、相机/相册/文件选择、系统返回手势和原生通知。
通知在应用进程存活时可即时显示，系统后台任务还会定时检查遗漏消息；设置里的“通知诊断”会分别验证系统权限、本地通知通道和 Mac 消息轮询。Android 的省电策略仍可能延迟 15 分钟后台检查，真正秒级的应用退出后推送还需要给 APK 配置 Firebase Cloud Messaging。
在 Android 手机上下载 APK 后允许安装即可；开发机也可以执行：

```bash
cd android
export ANDROID_HOME="$HOME/Library/Android/sdk"
./gradlew assembleDebug
```

这是个人测试用的 debug APK，不是 Google Play 发布包。Mac 后端和手机连接方式见 [`backend/README.md`](backend/README.md)。
