# Dwell v0.4.3：聊天导航与底部卡片交互修复设计

日期：2026-08-09  
状态：方案 2 已获用户确认，等待书面规格复核

## 1. 本次目标

本次版本集中修复两个已经影响使用的回归：

1. 恢复旧版日记卡片顺滑、跟手、可预测的拖拽手感，并让所有底部卡片共用同一套物理反馈。
2. 把聊天首页、新会话入口和聊天历史页补成一条完整、可持续使用的导航链路。

本设计是对 v0.4.2 设计文档中“统一底部卡片控制器”和“会话列表”部分的修订。其余离线、远程连接、定时任务和生活数据设计继续保留。

## 2. 已确认的用户决策

- 采用方案 2：保留现有单页 Web 前端、Node.js 后端和 Android WebView 壳，重构卡片手势层与聊天导航，不做原生 Android 重写。
- App 进入并完成过渡画面后，显示一条全新的空白会话。
- 空白会话不立即写入历史；只有发送第一条消息时才创建会话记录。
- 所有底部卡片都采用旧版日记卡片的拖拽手感。
- 卡片任意非按钮位置均可开始拖动，文字和图标作为卡片内容保持固定，不单独位移或被遮盖。
- 聊天历史页支持搜索、全部/已归档筛选、多选归档和恢复。
- 不提供永久删除，避免误删会话。
- 新版本按小版本发布为 v0.4.3。

## 3. 当前问题与根因

### 3.1 卡片手势回归

旧版日记详情只在明确的拖拽区域接管触摸，拖动时整体使用 transform 位移，松手后以短动画复位或关闭。新版增加了通用整卡拖拽控制器，并同时保留 Add to chat 自己的高度拖拽控制器，造成以下问题：

- 正文滚动与卡片拖动争夺同一触摸序列。
- Add to chat 在拖动中改变 height，引发布局重排，图标和文字会挤压、遮盖或跳动。
- 不同卡片使用不同阈值、时长和吸附逻辑，手感不一致。
- 最大展开状态可能丢失顶部圆角或边框，看起来像错误的全屏页面。
- 轻点按钮和拖动之间缺少稳定的意图判定，容易误触或不响应。

### 3.2 启动状态不是新会话

页面启动后直接读取后端“当前会话”并加载历史，因此重新打开 App 会回到旧内容。现有后端已经支持 armed new chat：先进入空白状态，第一条消息发送时才真正创建会话。缺少的是启动时自动进入该状态，以及打开历史会话时避免再次被启动逻辑覆盖。

### 3.3 聊天首页头部不符合目标

当前头部中央显示 Claude / Claude Code，右上角只有一个幽灵图标。目标聊天页需要：

- 左上角菜单按钮。
- 右上角圆形新会话按钮。
- 最右侧更多菜单按钮。
- 会话内容从头部下方自然滚动，头部不占用中央标题空间。

### 3.4 聊天历史页功能不完整

现有 Chats 页面只有简化卡片列表，没有目标截图中的大标题、搜索框、扁平列表、筛选、批量管理和浮动 New chat 按钮。侧边栏“聊天”入口也没有完整接入该页面。

## 4. 采用的结构

### 4.1 单一手势引擎，按卡片配置吸附点

实现一个 BottomSheetMotion 控制器。所有底部卡片只使用这一套指针状态机和动画曲线，不再各自绑定 touch 或 pointer 处理器。

控制器包含四个状态：

- idle：卡片静止在吸附点。
- pending：手指已按下，尚未超过拖动容差，按钮点击仍然有效。
- dragging：确定为纵向拖动，捕获指针并整体移动卡片。
- settling：松手后向目标吸附点运动。

卡片通过配置决定可用状态：

- Add to chat：closed、collapsed、expanded。
- 日记详情：closed、collapsed、expanded。
- Sources：closed、collapsed、expanded。
- Summary：closed、collapsed、expanded。
- Thought process：closed、collapsed、expanded。
- 其他真正的底部卡片沿用相同三档；全屏页面和侧边栏不接入底部卡片控制器。

### 4.2 只移动卡片，不重排内容

卡片在打开时一次性确定最大几何尺寸，拖动和吸附只修改 translate3d 与遮罩 opacity：

- 不在 pointermove 中修改 height。
- 不在拖动时重新排版内部网格或列表。
- 图标、文字、分隔线和按钮始终固定在卡片坐标系内。
- 最大展开状态仍保留顶部圆角、边框和阴影。
- expanded 顶边与屏幕顶部保持 max(安全区 + 12px, 48px) 的间距，不变成全屏。

### 4.3 旧日记手感作为基线

旧版日记交互是本次唯一的手感基准：

- 手指向下时卡片一比一跟随。
- 超过上边界时使用旧版相同的阻尼感，不允许硬顶到状态栏。
- 未达到切换阈值时，以约 200ms 的短 ease 动画回到原吸附点。
- 达到切换阈值时，移动到相邻吸附点；从 collapsed 继续向下可关闭，从 expanded 向下先回到 collapsed。
- 快速甩动可按速度方向选择相邻吸附点，但不得一次越过两个状态。
- 遮罩随卡片位置连续变化，不闪烁、不突然跳明暗。

具体阈值以旧日记的 110px 释放距离、向上约三分之一阻尼和约 200ms 复位动画为初始值，再在三星 S25+ 尺寸上校准。统一后任何卡片不得单独覆盖这些参数。

### 4.4 点击、拖动和正文滚动仲裁

拖动可从卡片任意非交互区域开始，包括空白处和普通文字区域。交互仲裁规则为：

1. 按下后先进入 pending，移动小于 8px 时仍按轻点处理。
2. 明确纵向移动并超过容差后才进入 dragging，并取消本次合成点击。
3. 按钮、输入框、开关、链接和文件选择项轻点时优先执行自身行为。
4. 用户从这些控件上按下后若形成明确纵向拖动，也允许整张卡片接管；松手不得误触控件。
5. collapsed 状态向上拖动时优先展开卡片，内部列表不抢滚动。
6. expanded 状态下，内部正文可以正常滚动。
7. expanded 状态向下滑时，如果正文 scrollTop 大于 0，先滚正文；到达顶部并继续下拉后，无跳变地交给卡片。
8. 卡片开始拖动后，内部元素只随卡片整体移动，不改变自身布局、层级或可见性。

Android 系统返回键和左上角关闭按钮都直接关闭当前卡片，不要求用户必须拖动。

## 5. 主聊天页

### 5.1 顶部操作区

聊天页面头部采用目标截图布局：

- 左侧：菜单按钮，点击打开侧边栏。
- 右侧第一项：深色圆形加号按钮，点击进入全新空白会话。
- 右侧第二项：竖向更多按钮，打开当前会话菜单。
- 移除头部中央 Claude / Claude Code 标题，给正文保留空间。

更多菜单只提供安全且真实的操作：

- 重命名当前会话。
- 归档当前会话。

当前仍是未发送消息的空白会话时，更多菜单禁用重命名和归档，并说明“发送第一条消息后可管理”。

### 5.2 新会话状态

App 完成启动过渡后执行以下流程：

1. 调用现有 api/newchat，将后端置为 armed 状态。
2. 清空当前消息视图、输入草稿和会话级临时状态。
3. 显示欢迎区域和空白输入框。
4. 此时不创建 chat ID，也不出现在历史列表中。
5. 用户发送第一条消息时，由后端原子地创建会话，再保存用户消息和回复。

重复点击右上角新会话按钮时：

- 如果当前已经是未发送的空白会话，不重复创建或提示。
- 如果当前有内容，切换到新的 armed 空白状态。
- 未发送的输入草稿在切换前保存在本地草稿区，不写成聊天历史。

### 5.3 打开历史会话

选择历史会话不通过整页 reload 完成。前端执行显式的 openConversation 流程：

1. 请求后端切换到指定 chat ID，并取消 armed 状态。
2. 停止旧会话的轮询或流式订阅。
3. 清理当前消息 DOM 和游标。
4. 加载所选会话的完整消息历史。
5. 重新建立该会话的增量更新。
6. 关闭 Chats 页面并回到主聊天页。

这样启动时的“自动新会话”只在真正的文档启动发生，不会覆盖用户刚选中的历史会话。

## 6. Chats 历史页

### 6.1 页面结构

Chats 是独立全屏页面，不是可拖动底部卡片。布局按目标截图实现：

- 顶部左侧菜单按钮。
- 顶部右侧筛选按钮和管理按钮。
- 大号衬线标题 Chats。
- 标题下方为圆角描边搜索框。
- 会话使用扁平列表，不使用多层卡片背景。
- 每项第一行显示会话标题，第二行显示相对时间或日期。
- 右下角固定深色圆角 New chat 浮动按钮。

### 6.2 搜索与排序

- 默认按 last 时间倒序排列。
- 搜索同时匹配会话标题和最近消息摘要。
- 输入搜索词时即时过滤，不改变服务器数据。
- 最近七天优先显示相对时间；更早记录显示本地日期。
- 无结果时显示“没有找到会话”，并保留清空搜索入口。

### 6.3 筛选

筛选按钮提供：

- 全部。
- 进行中。
- 已归档。

默认显示全部，从而满足“看到所有会话记录”。筛选状态只影响列表显示，不修改会话。

### 6.4 管理模式

点击管理按钮进入多选模式：

- 每条会话显示选择控件。
- 顶部显示已选数量和取消。
- 进行中的会话可批量归档。
- 已归档会话可批量恢复。
- 混合选择时分别执行适用动作，并返回逐项结果。
- 不提供永久删除。
- 操作失败的会话保留选中状态并显示原因，成功项立即更新。

### 6.5 New chat

浮动 New chat 按钮和主聊天页右上角加号共用同一动作：

- 关闭 Chats 页面。
- 进入 armed 空白会话。
- 不立即创建历史记录。

### 6.6 侧边栏入口

侧边栏“聊天”按钮不再只标记当前栏目，而是打开 Chats 历史页。Chats 页左上角菜单仍可重新打开侧边栏，保持和主聊天页一致的导航。

## 7. 后端与数据契约

继续复用现有 chat 存储和首条消息建会话机制，仅补齐列表与批量动作契约：

- GET api/chats?scope=all：返回进行中与已归档会话。
- GET api/chats?scope=live：返回进行中会话。
- GET api/chats?scope=archived：返回已归档会话。
- POST api/chats action=switch：打开指定会话并取消 armed。
- POST api/chats action=rename：修改标题。
- POST api/chats action=archive：归档单个会话。
- POST api/chats action=restore：恢复单个会话。
- POST api/chats action=bulkArchive：批量归档。
- POST api/chats action=bulkRestore：批量恢复。
- POST api/newchat arm=true：进入未落库的新会话状态。

接口要求：

- 批量动作返回每个 ID 的成功或失败结果，不允许整批静默失败。
- scope=all 中每项必须包含 id、name、preview、last、archived 和 current。
- 空白 armed 会话不返回到任何聊天列表。
- 归档当前会话后，主页面自动进入新的 armed 空白会话。
- 恢复操作不自动切换当前会话。

网络不可用时，Chats 页显示最近一次本地缓存并标记离线；归档、恢复和重命名不伪造成功。用户可以浏览已有缓存，但需要联网才能提交管理动作。

## 8. 视觉与触摸细节

- 所有可点击图标的真实触摸区域至少 48 × 48 CSS px。
- 顶部操作避开 Android safe-area。
- 主聊天页、Chats 页和底部卡片使用同一图标尺寸与线宽体系。
- 卡片最大展开时顶部圆角清晰可见，不与白色页面背景融为一体。
- 拖动期间仅移动合成层，不触发布局抖动。
- prefers-reduced-motion 开启时缩短吸附动画，但保留状态变化。
- 键盘弹出后重新计算可视区域，输入框和卡片吸附点不得跳出屏幕。

## 9. 验收场景

### 9.1 卡片

对 Add to chat、日记详情、Sources、Summary 和 Thought process 逐一验证：

1. 慢速拖动时卡片一比一跟手。
2. 小幅拖动松手后自然回弹。
3. 上拉可展开，下拉可缩小，再下拉可关闭。
4. 最大展开仍离顶部保留间距、圆角和边框。
5. 从卡片空白、普通文字和图标附近开始拖动均不会让内部内容移位。
6. 点击 Camera、Photos、Files、来源链接和关闭按钮仍正常响应。
7. 拖动经过按钮后不会误触。
8. 长正文先滚动，到顶后继续下拉能无跳变接管卡片。
9. 快速连续拖动不会卡死、闪烁或停在任意中间位置。
10. Android 返回手势可关闭最上层卡片。

### 9.2 会话

1. 冷启动过渡结束后显示空白新会话。
2. 不发送消息直接退出，历史列表不新增空记录。
3. 发送第一条消息后，历史列表新增且可重新打开。
4. 主聊天页右上角加号立即进入新空白会话。
5. 右上角更多菜单可以重命名和归档已有会话。
6. 侧边栏“聊天”进入 Chats 页。
7. Chats 默认显示全部会话，并能搜索标题和摘要。
8. 筛选进行中和已归档正确。
9. 多选归档、恢复正确，且没有永久删除入口。
10. 点击历史会话返回主聊天页并显示完整内容，不会被自动空白会话覆盖。
11. New chat 浮动按钮与主页面加号行为一致。
12. 离线时可读缓存并明确标记，不把管理动作显示成成功。

### 9.3 发布

- Android versionName 为 0.4.3，versionCode 递增。
- debug APK 完成签名检查和安装包完整性检查。
- Web 前端脚本通过语法检查。
- 后端聊天接口通过最小回归测试。
- 在三星 S25+ 对应视口检查头部、安全区、键盘和底部卡片。
- APK、源码提交和 GitHub Release 指向同一提交。

## 10. 非目标

- 不重写为原生 Android 或 Jetpack Compose。
- 不永久删除聊天记录。
- 不为 Chats 页添加云端账号体系。
- 不改变 Claude Code 的模型路由。
- 不在本版本重做日记、待办等业务数据模型。
- 不用装饰性按钮冒充尚未实现的功能。
