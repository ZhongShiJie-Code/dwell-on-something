# Dwell v0.4.2：移动端交互、离线同步、会话卡片与 Claude Desktop 定时任务设计

日期：2026-08-09  
状态：已完成用户分段确认，等待书面规格复核

## 1. 目标

本次版本不是继续叠加静态页面，而是修正当前 Android 应用中交互不一致、演示数据冒充真实数据、离开局域网后不可用以及会话动作缺失的问题。最终交付物为三星 S25+ 可安装的 `v0.4.2` APK、对应源码和 GitHub Release。

本版本必须达到以下结果：

1. `Add to chat`、日记详情、Sources、Summary 和 Thought process 使用同一套顺滑、跟手、可预测的底部卡片交互。
2. 所有左上角关闭按钮都容易点击，并正确避开 Android 状态栏。
3. 侧边栏彻底删除 Recents、Claude 和“另一位”区域。
4. 手机可查看 Claude Desktop 的真实定时任务，并执行“立即运行、暂停、恢复”。
5. 清单不再出现“欣欣、老公、顾屿”等原作者示例称呼；所有清单操作都真实生效。
6. 应用以非局域网使用为主要场景，同时保留完全离线时的本地生活数据能力。
7. Claude 回复具有真实来源、摘要、思考过程和完整动作栏；所有按钮都有实际功能。

## 2. 当前问题与根因

### 2.1 底部卡片

当前 `Add to chat` 通过修改 `height` 在收起和展开之间切换，拖动时会触发布局重排，内容会被挤压或遮挡。日记详情主要通过整体位移表现拖动，因此手感更稳定。不同页面各自维护手势逻辑，造成速度、吸附点、关闭阈值和边框表现不一致。

### 2.2 关闭按钮

页面和卡片分别定义关闭按钮，视觉位置和真实点击区域不一致。部分按钮靠近状态栏，视觉上看得到但有效触摸区域偏小或被安全区挤压。

### 2.3 Recents 与错误称呼

Recents、“Claude”、“另一位”以及清单里的“欣欣、老公、顾屿”均为前端硬编码。清单中一组事项还被显式传入不可交互状态，因此点击复选框和文本没有响应。

### 2.4 会话消息

当前前端围绕一个全局流式回复节点持续追加内容，缺少稳定的“每轮会话”数据模型。代码块可以复制，思考过程有单独弹层，但消息没有独立绑定来源、摘要、反馈、播放、分享或重试状态。只添加图标会产生没有真实数据和行为的假功能。

### 2.5 网络与离线

APK 当前只保存单一 API 地址。没有局域网/远程端点优先级，也没有持久化离线数据层或同步队列。未连接后端时的演示数据只存在于运行内存，重启后会丢失。

### 2.6 Claude Desktop 定时任务

Claude Desktop 的定时任务状态由桌面端自身管理。任务的周期、模型和启用状态不应通过直接改写 `scheduled-tasks.json` 控制，因为桌面端运行时可能覆盖文件。手机端需要一个只暴露允许动作的 Mac 侧桥接模块。

## 3. 方案选择

### 方案 A：只修界面

保留现有消息和数据结构，只补图标、卡片样式与点击事件。开发量较小，但来源、反馈、重试和离线同步仍会互相缠绕，后续继续出现假按钮和数据丢失。本方案不采用。

### 方案 B：在现有技术栈内做结构化升级（采用）

保留单页 Web 前端、Node.js 后端和 Android WebView 壳，增加统一卡片控制器、结构化会话模型、IndexedDB 离线仓库、连接管理器、Android 原生动作桥和 Claude Desktop 定时任务桥。该方案能解决根因，同时避免重写整个应用。

### 方案 C：重写为完全原生 Android

原生列表和手势可以获得更高的系统一致性，但会复制全部生活页面和业务逻辑，发布风险、工期和维护成本都过高。本版本不采用。

## 4. 页面与交互设计

### 4.1 统一底部卡片控制器

新增一个单一职责的 `BottomSheetController`，供以下页面复用：

- Add to chat
- 日记详情
- Sources
- Summary
- Thought process

控制器使用固定最大高度的卡片，通过 `transform: translate3d(0, y, 0)` 移动整张卡片，不在拖动过程中修改 `height`。这样内容、图标、边框和圆角始终固定在卡片内部，不发生重排。

卡片具有三个稳定状态：

- `collapsed`：默认露出 47dvh；软键盘打开时按可视视口重新计算，保证标题和首组操作可见。
- `expanded`：卡片顶边固定为 `max(env(safe-area-inset-top) + 12px, 48px)`，不成为全屏页面。
- `closed`：卡片移出屏幕并解除遮罩和焦点锁定。

手势规则：

- 从 collapsed 向上拖动，卡片跟手展开。
- 从 expanded 向下拖动，先吸附回 collapsed；继续向下拖动可关闭。
- 松手时结合位移和速度决定吸附目标；快速甩动优先使用速度方向。
- 向上超过 expanded 时加入阻尼，不允许卡片顶穿安全间距。
- 卡片任意位置都能开始拖动，但表单输入、滚动列表和按钮保持自身行为。
- 触点移动超过点击容差后取消按钮点击，防止拖动时误触图标。
- 内容超过卡片可用高度时，先由内部列表滚动；列表到达顶部后继续下拉才接管卡片拖动。
- 遮罩透明度随卡片位置连续变化，不在吸附时突然跳变。

动画只使用 transform 和 opacity。短距离吸附使用 220 毫秒，跨状态吸附使用 300 毫秒，并采用同一条自然减速曲线；手指按住期间不使用 transition，确保一比一跟手。

### 4.2 统一关闭按钮

所有左上角关闭按钮使用同一组件：

- 真实点击区域至少 48 × 48 CSS 像素。
- 可见图标约 20 × 20 CSS 像素，使用统一线宽。
- 顶部位置包含 `env(safe-area-inset-top)`，不会贴住状态栏。
- 左侧视觉边距保持一致；页面和底部卡片不再各自写绝对坐标。
- 按下时提供轻微缩放或透明度反馈。
- 保留 Android 系统返回手势，与关闭按钮执行相同状态转换。

### 4.3 Add to chat

Add to chat 继续保留 Camera、Photos、Files、Web search、Add to project、Tool access 和 Connectors。图标、文字尺寸、行高、卡片内边距和分隔线按用户截图统一校准。

Camera、Photos 和 Files 调用现有 Android 文件选择能力；Web search 开关写入当前会话设置；Add to project、Tool access 和 Connectors 显示真实后端状态。未实现或不可用的选项必须显示原因，不能保持可点击但无响应。

### 4.4 侧边栏

完全删除 Recents 标题、Claude、“另一位”及相关事件处理代码。侧边栏保留当前生活功能，并增加“定时任务”入口。页面标题使用 `Claude` 或 `ShiJie` 的位置不应再承担“最近会话”用途。

### 4.5 清单

清单分为：

- 我的清单：归属 `ShiJie`
- Claude 的清单：归属 `Claude`

删除所有关系型示例称呼和演示任务。空状态分别显示“还没有事项”和“Claude 还没有添加事项”。

交互规则：

- 点击复选框切换完成状态，并立即写入本地数据库。
- 点击事项文字打开编辑卡片，可修改内容和时间。
- 支持在两个分区新增事项；来源字段决定显示在相应分区。
- 删除操作使用明确按钮，并允许短时间撤销。
- 同步失败时保留本地状态并显示待同步标记，不回滚用户刚才的操作。

### 4.6 Claude Desktop 定时任务

侧边栏新增“定时任务”页面。每项显示：

- 名称和简短说明
- 周期描述
- 启用或暂停状态
- 最近运行时间
- 最近结果：成功、失败、跳过或尚未运行
- “立即运行”动作
- “暂停/恢复”动作

手机端不提供新建、编辑、删除和模型修改。操作提交后先显示进行中状态，后端返回真实结果后再更新；请求失败时恢复原状态并显示明确原因。

## 5. 会话消息设计

### 5.1 结构化会话轮次

每一轮会话使用独立记录，不再依赖一个全局回复 DOM 节点。记录至少包含以下字段：

```text
ChatTurn
  id
  chatId
  userMessageId
  assistantMessageId
  promptText
  responseText
  sources[]
  summary
  thoughtProcess
  toolEvents[]
  feedback
  speechState
  status
  createdAt
  completedAt
```

流式内容更新当前 `ChatTurn`，完成后形成不可变的已完成版本。重新生成会创建新的回复版本并保留旧回答，不覆盖历史内容。

### 5.2 Sources

仅当该条回复具有真实 URL 或工具返回的来源记录时显示 `Sources` 按钮。来源记录包含标题、站点、URL 和可选图标。来源去重后按首次使用顺序显示。

点开后使用统一底部卡片：

- 收起态显示前几项，向上拖动查看完整列表。
- 每项单行或双行截断，保留站点名称。
- 点击来源通过 Android 外部浏览器打开，不在聊天 WebView 内吞掉返回路径。
- URL 无法打开时显示错误，不生成替代或猜测来源。

来源提取优先使用工具事件中的结构化 URL，其次解析最终回复中的明确链接。没有可靠来源时不显示 Sources。

### 5.3 Summary 与 Thought process

当后端实际收到思考内容或工具执行轨迹时，消息可显示 Summary 入口。Summary 卡片展示简短摘要；点击条目进入 Thought process 卡片查看可用的完整内容。

以下规则必须成立：

- 不凭空生成思考过程。
- 后端未提供思考内容时，只显示工具执行摘要或完全隐藏入口。
- 流式思考、工具调用和最终回复都归属同一个 ChatTurn。
- Summary 与 Thought process 使用统一底部卡片手势和统一关闭按钮。

### 5.4 回复动作栏

每条完成的 Claude 回复下方按顺序显示：

1. 复制：复制纯文本正文，成功后短暂变为完成状态。
2. 转发：调用 Android 系统分享面板，分享正文；来源存在时可附带来源链接。
3. 播放：调用 Android 原生 TextToSpeech。播放中按钮变为暂停/停止状态；切换会话或开始播放另一条时终止上一条。
4. 赞：保存正向反馈，可再次点击撤销。
5. 踩：保存负向反馈，与赞互斥，可再次点击撤销。
6. 重新生成：用原始用户问题在同一会话中发起新回复，保留旧回复。如果原轮包含可能修改文件或外部状态的工具操作，重新运行前显示确认卡片。

动作按钮使用统一图标尺寸、线宽、点击区域和按下反馈。发送中的回复不显示重试、赞踩等完成态动作。

## 6. 离线优先与同步

### 6.1 连接顺序

连接管理器维护两个可配置端点：

1. 局域网 Mac 地址
2. Cloudflare 远程地址

每次启动和网络变化后，以短超时并行探测健康状态；局域网健康时优先使用局域网，否则使用 Cloudflare。两者都不可用时进入离线模式。界面只显示轻量状态，不使用反复弹窗。

### 6.2 本地数据仓库

使用 IndexedDB 保存：

- 清单
- 日历
- 日记
- 便条、清单、日历、日记、悄悄话、墙、共读进度和批注
- 健康、日报和仓库时间线的最近一次只读快照
- 会话列表与消息缓存
- 未发送聊天草稿
- 定时任务最后一次成功读取的只读快照
- 待同步修改队列

演示数据不再作为真实默认数据写入。首次安装且没有服务器数据时显示干净空状态。

### 6.3 同步协议

每个可同步实体具有稳定 ID、`updatedAt`、`deletedAt`、设备 ID 和修订号。客户端写操作流程为：

1. 先提交到 IndexedDB。
2. 更新界面。
3. 写入带唯一 mutation ID 的同步队列。
4. 有连接时提交到后端。
5. 后端以 mutation ID 保证重复提交不会产生重复数据。
6. 成功后更新同步游标并移除队列项。

普通布尔状态和短字段按最新修订处理。日记、长文本或批注发生并发冲突时，保留服务器版本并创建标注为“冲突副本”的本地版本，禁止静默覆盖。

聊天发送不进入自动同步队列。完全离线时，输入内容保存为草稿并显示“离线 · 已保存草稿”；网络恢复后必须由用户再次点击发送。

## 7. Cloudflare 远程连接与安全

现有 `cloudflared` Tunnel 可复用。Dwell 使用一个专用主机名和独立 ingress 规则，将远程 HTTPS 请求转发到 Mac 的 `127.0.0.1:8787`。主机名由安装时配置提供，不写死在源码。远程入口前必须配置 Cloudflare Access，不能只依赖一个公开 URL。

首次设置流程：

1. 用户在 APK 中填写或扫描 Cloudflare Dwell 地址。
2. APK 在同一 WebView 会话中完成 Cloudflare Access 身份登录。
3. APK 与 Mac 后端执行一次性设备配对。
4. 设备凭据写入 Android Keystore 保护的本地存储。
5. 后续请求同时通过 Cloudflare Access 和 Dwell 设备鉴权。

安全要求：

- Cloudflare API Token、Access 服务凭据和 Dwell 设备令牌不得提交 Git。
- APK 不包含固定的生产密钥。
- 后端继续校验自己的授权信息，不能仅相信请求来自 Tunnel。
- CORS 只允许 APK 的受控 WebView origin 和明确配置的管理页面。
- WebView 禁止导航到任意网页；外部链接交给系统浏览器。
- 设备令牌可在 Mac 后端撤销。
- 日志不得输出完整令牌、Cookie、用户消息正文或上传文件内容。

Cloudflare Tunnel 只负责把公共主机名映射到本地服务；Cloudflare Access 负责在流量到达后端前检查身份。参考：

- <https://developers.cloudflare.com/tunnel/setup/>
- <https://developers.cloudflare.com/cloudflare-one/access-controls/applications/choose-application-type/>
- <https://developers.cloudflare.com/cloudflare-one/access-controls/access-settings/session-management/>

## 8. Claude Desktop 定时任务桥

新增 Mac 侧 `desktop-tasks` 模块，职责仅为读取 Claude Desktop 任务并执行允许动作。它不直接改写桌面端 JSON 文件。

本机核查确认 Claude Desktop 内置的 `scheduled-tasks` MCP 支持列出任务，并可通过 `update_scheduled_task` 的 `enabled` 字段暂停或恢复任务；桌面端内部调度器另有 `runNow` 能力，但没有对普通外部进程开放稳定 API。因此桥接分为两个明确通道：

- 读取：只读解析当前 Claude-3p profile 的 `scheduled-tasks.json` 和每项 `SKILL.md` 描述，绝不写入这些文件。
- 动作：使用已获 macOS 辅助功能授权的本机 GUI 控制器操作 Claude Desktop 的 Routines 界面。暂停/恢复触发桌面端自己的更新流程；立即运行点击桌面端自己的 Run now。每个动作完成后重新读取任务状态或运行会话，确认桌面端确实接受了操作。

GUI 控制仅在 Claude Desktop 版本、profile、辅助功能授权和关键界面元素均通过启动自检时启用。自检失败时手机端按钮置灰并显示 `desktop_control_unavailable`，不得回退到直接修改 JSON，也不得显示假成功。

对手机暴露的最小接口：

```text
GET  /api/desktop-tasks
POST /api/desktop-tasks/:id/run
POST /api/desktop-tasks/:id/pause
POST /api/desktop-tasks/:id/resume
```

桥接模块必须通过上述 Claude Desktop Routines 控制路径完成动作，并在返回前重新读取状态确认结果。若桌面端未运行、Mac 睡眠、辅助功能权限缺失、界面版本不匹配、任务不存在或调用超时，接口返回可区分的错误码，前端不伪造成功状态。

任务列表允许离线缓存，但所有动作都要求 Mac 在线。缓存页面必须显示“上次更新于”，避免把旧状态冒充实时状态。

Claude 官方说明本地定时任务需要桌面端打开且电脑保持唤醒：

- <https://code.claude.com/docs/en/desktop-scheduled-tasks>

## 9. Android 原生能力

保留现有相机、相册、文件选择、语音输入、返回手势和通知能力，并扩展 NativeBridge：

- `shareText`：打开 Android `ACTION_SEND` 系统分享面板。
- `speak`、`stopSpeaking`、`speechState`：控制 TextToSpeech 并回传状态。
- 安全凭据读写：由 Android Keystore 保护，不通过 localStorage 持久化。
- 外部链接：使用系统浏览器 Intent。
- 网络状态：通知 Web 层重新探测连接，但不直接触发聊天发送。

本地 Web 内容应使用稳定、安全的应用资源 origin，避免继续依赖权限边界模糊的 `file://`。所有 JavascriptInterface 方法限定参数长度和允许操作，页面离开受控 origin 时移除桥接接口。

## 10. 错误和状态处理

必须覆盖以下用户可见状态：

- Mac 未在线：生活数据可用；聊天和任务动作禁用，并保留草稿。
- Cloudflare 登录过期：引导重新登录，不清除本地数据。
- 局域网失效但 Cloudflare 可用：静默切换并显示一次轻量提示。
- 同步失败：项目显示待同步标记，并使用退避重试；不回滚本地编辑。
- 定时任务动作失败：恢复原开关状态并显示具体错误。
- 来源打不开：保留来源条目并提示系统浏览器无法打开。
- TTS 不可用：提示检查 Android 文字转语音服务，不播放假动画。
- 重新生成失败：保留旧回复和原始问题，可再次尝试。
- Access 或应用鉴权失败：区分重新登录和重新配对，不笼统显示“网络错误”。

## 11. 测试与验收

### 11.1 自动测试

- 扩展后端 smoke test，覆盖清单编辑、同步幂等、消息元数据、反馈、重试、任务列表及动作错误。

## 12. 组件边界与实施顺序

为避免继续在单一 `web/index.html` 中堆叠全局状态，本次允许做与需求直接相关的拆分：

1. `BottomSheetController`：只负责卡片位置、手势和吸附。
2. `ChatTurnStore`：只负责会话轮次、来源、摘要、反馈和重试关系。
3. `OfflineStore`：只负责 IndexedDB 和同步队列。
4. `ConnectionManager`：只负责局域网、Cloudflare 和离线状态选择。
5. `NativeActions`：只负责分享、TTS、外部链接和安全凭据。
6. `DesktopTasksBridge`：只负责 Claude Desktop 任务只读解析、自检、Routines 界面操作与结果复核。

实施顺序为：先建立数据和连接边界，再统一底部卡片和关闭按钮，然后修清单与侧边栏，再补会话卡片和原生动作，最后接入定时任务、Cloudflare、安全配对和离线同步。每一阶段通过对应自动测试后再进入下一阶段。

## 13. 明确不在 v0.4.2 范围内

- 手机端新建、编辑或删除 Claude Desktop 定时任务。
- 在 Mac 关机或睡眠时运行 Claude Desktop 本地任务。
- 完全重写为原生 Android UI。
- 自动发送离线期间保存的聊天草稿。
- 伪造来源、摘要或思考过程来填满界面。
- 将 Cloudflare、Claude、第三方模型或 GitHub 的生产密钥写入仓库或 APK。
